工作区布局设计（文字 / 图片 / 视频）

一、设计目标

- 工作区是统一的 AI 创作入口，同一页面可直接切换文字、图片、视频生成。
- 页面采用“左侧会话栏 + 右侧主工作区”，交互方式接近常用 LLM 对话产品。
- 每次点击右下角圆形向上箭头按钮，都在当前会话中追加一个新的生成回合。
- 每个回合先展示用户本次使用的关键词，再展示生成状态与结果，主内容区形成连续滚动的对话流。
- 模型能力决定编辑器中出现的素材入口和参数，不展示模型不支持的选项。
- 顶部不展示厂商分组质量、响应时长等监控信息，也不设置常驻厂商/模型侧栏。

布局说明：

1. 顶部站点导航与“创作案例”首页保持一致；进入工作区后不再显示装饰性横幅。
2. 会话栏建议宽 260～288px，主工作区占据剩余空间；会话内容最大阅读宽度约 1080～1200px并居中。
3. 会话内容区独立纵向滚动，编辑器吸附在主区底部，不随历史内容滚出视口。
4. “文字生成 / 图片生成 / 视频生成”使用页签式切换，当前类型使用蓝色高亮。
5. 切换生成类型时保留各类型尚未提交的提示词、素材和参数草稿；不会把旧类型的参数带入新类型。
6. 厂商与模型在主区顶部按“厂商 → 模型”顺序选择，不占用编辑器右下角；模型列表只显示当前厂商的模型。
7. 编辑器右下角的固定顺序为：模型分组、余额、提交按钮，不插入其他控件。

- 新建会话后进入空状态，并默认继承当前生成类型，不继承上一会话的提示词和素材。

- 点击历史会话恢复其生成类型、回合记录和当时使用的模型信息；编辑器恢复该会话对应类型的草稿。


四、厂商、模型与分组选择

- 顶部依次显示厂商和模型下拉框，编辑器操作区保留模型分组下拉框，完整选择顺序为“厂商 → 模型 → 分组”。
- 只列出当前生成类型可用的厂商和模型；图片页不出现纯视频模型，视频页不出现纯图片模型。
- 模型列表按厂商过滤；模型分组只列出 abilities 中已关联当前模型且用户有权使用的分组。
- 切换模型后，保留提示词及新模型兼容的素材和参数；不兼容项被清除前给出明确提示。
- 如果原模型分组对新模型不可用，自动切换至推荐分组，并提示“已切换为该模型可用的分组”。
- 模型下线或暂无可用渠道时置灰，显示原因，不允许确认选择。
- 文本工作台不提供温度和单次响应最大 token 数选项，调用时使用上游默认值。
- 点击生成时必须存在与所选分组精确匹配且可用于当前模型的平台 API Key；否则弹出缺少 Key 提示，并可跳转到 Key 创建页且预填分组。

八、模型分组、余额与提交

编辑器右下角固定布局：

┌───────────────────────────────────────────────────────────────┐
│ [模型分组：稳定优先⌄]  │  [余额 ¥88.00]  │  [ ↑ ]           │
└───────────────────────────────────────────────────────────────┘

- 模型分组弹层只列出当前模型可用分组，包含分组名称、简短说明和预计消耗差异。
- 切换模型后重新读取可用分组；原选择仍兼容则保留，否则切换到推荐分组。
- 点击余额打开余额明细或充值入口；余额旁可显示“预计消耗 ¥x.xx”，但不得改变三个控件的顺序。
- 提交按钮为空闲时是蓝色圆形向上箭头；提交后当前回合进入生成状态，按钮变为停止/取消任务状态（仅模型支持取消时可用）。
- 余额不足时余额文字转为警示色，提交按钮禁用，点击余额可进入充值。


九、会话回合与滚动规则

每个回合统一由以下结构组成：

┌────────────────────────────────────────────────────────────────────────────┐
│ 关键词                                                                    │
│ “本次提交的完整关键词，可换行展示，不在默认状态下截断……”                  │
│ 模型名称 · 本次参数摘要 · 创建时间                                        │
│                                                                            │
│ ┌────────────────────────────────────────────────────────────────────────┐ │
│ │ 生成中 / 生成结果 / 失败状态                                           │ │
│ └────────────────────────────────────────────────────────────────────────┘ │
│ [结果操作……]                                                              │
└────────────────────────────────────────────────────────────────────────────┘

- 点击提交后立即创建回合并滚动到其顶部，生成过程中不锁住整个编辑器，可继续准备下一次输入。
- 用户停留在页面底部时，新状态和新结果自动跟随；用户已向上查看旧回合时，不强制跳到底部。
- 用户离开底部时显示悬浮按钮“↓ 返回最新内容”，点击后平滑滚动至最新回合。
- 多次点击“再次生成”分别创建新回合，不覆盖原结果；每个回合保留独立模型与参数摘要。
- 切换文字、图片、视频页签不会改变当前会话；各类型回合可以存在于同一会话中，并以类型图标区分。


十、关键状态

1. 空会话
   - 中央显示类型对应的引导语和 3～4 个示例关键词。
   - 不展示虚构的生成结果；编辑器保持可操作。

2. 排队 / 生成中
   - 结果卡显示“正在排队”或“正在生成”，并展示已知进度。
   - 无可靠进度时使用不确定进度动画，不伪造百分比。
   - 视频生成允许展示“可以离开页面，完成后通知”。

3. 生成失败
   - 原关键词和参数摘要保留。
   - 结果卡显示可理解的失败原因，以及“重试”和“重新编辑”。

4. 余额不足
   - 编辑器保留全部草稿和已上传素材。
   - 余额位置显示不足提示，提交按钮禁用，并提供充值入口。

5. 模型不可用
   - 历史结果仍正常显示。
   - 编辑器顶部提示当前模型不可用，要求选择其他模型；不静默替换模型。

6. 上传失败
   - 失败素材保留缩略占位并显示重试、删除，不影响其他已成功素材。


十一、案例页进入工作区

- 从案例全屏预览或案例卡片点击“进入工作台编辑”时，创建一个新会话。
- 自动切换到案例对应的图片或视频类型，并预填案例关键词、模型、参数和允许复用的参考素材。
- 若案例模型已不可用，保留关键词与兼容参数，模型位置显示“请选择可用模型”。
- 预填内容只进入编辑器，不自动提交；用户确认或调整后点击右下角按钮生成。

│ [⌕]  │                                                                     │
│      │                         会话内容区                                  │

│ ○    │                         吸底编辑器                                  │
└──────┴─────────────────────────────────────────────────────────────────────┘

- 桌面宽度不足时，会话栏先折叠为图标栏，主内容和编辑器保持完整。
- 更窄视口中会话栏改为覆盖式抽屉，由主区左上角按钮打开；关闭后不占用内容宽度。
- 模式页签空间不足时保持横向滚动，不把“文字 / 图片 / 视频”折叠成难以发现的菜单。
- 编辑器参数允许换行到第二行，但右下角“模型分组、余额、提交”保持为同一操作组并靠右。
- 本文档只定义窄屏降级策略，不另行定义完整移动端页面。


十三、视觉与可访问性说明

- 延续案例首页的近黑背景、深灰卡片、蓝色主操作色和弱描边；结果内容使用中性背景避免影响图片、视频观感。
- 所有纯图标按钮必须提供可访问名称和悬停提示；上传位、模型卡、参数项和会话项均可通过键盘操作。
- 弹层打开后焦点进入弹层，关闭后返回触发按钮；选项状态同时使用颜色、描边和选中标记表达。
- 正文、次要文字、禁用文字保持清晰层级，正文对比度满足 WCAG 2.1 AA。
- 所有用户可见文案接入 i18n，不在组件中硬编码单一语言。
